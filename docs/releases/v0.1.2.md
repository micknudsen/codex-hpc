# codex-hpc v0.1.2

This release adds Bubblewrap and common coding tools to the signed Linux x86-64 image. Codex remains at version 0.170.0.

## Changes

- Add Bubblewrap (`bwrap`) for the Codex Linux sandbox. The compute node must allow Bubblewrap to create user namespaces inside Apptainer.
- Add Python virtual environments with pip, GCC, G++, Make, and `jq`.
- Add Node.js 24.22.3 LTS with npm and npx.
- Check the Bubblewrap options that Codex needs. The image probe creates a Python virtual environment, builds and runs C and C++ programs, reads JSON, and runs an npm script offline.

## Installation and upgrade

```sh
conda create -n codex-hpc --override-channels -c micknudsen -c conda-forge codex-hpc=0.1.2
conda activate codex-hpc
codex-hpc setup --host my-cluster
codex-hpc connect '~/projects/example' --host my-cluster
```

If you already have an environment, install `codex-hpc=0.1.2` from the same channels. Run `codex-hpc setup` again to activate the new image and matching helper.

The client requires Python 3.9 or later and supplies OpenSSH. The login host needs Python 3, curl, and Apptainer with PEM signature verification. First-time setup needs access to GitHub Releases. Compute nodes need Linux x86-64, Slurm, and compatible Apptainer. They also need SSH access through the login host and access to the shared workspace and codex-hpc directories.

## Validation and limitations

All 12 Linux and macOS product-test jobs and signed-image qualification passed for the tool changes. Qualification tested a fresh Conda installation with the signed image. [Tool changes and CI](https://github.com/micknudsen/codex-hpc/pull/43)

Automated tests use controlled SSH, Slurm, and sign-in services. This image still needs validation on a representative cluster with real sign-in and sandboxed Codex tool calls. Each session uses one workspace and one Linux x86-64 node and task.
