# codex-hpc v0.1.1

Patch release fixing the missing code-mode host in the container image used by
Codex command and file-editing tools. Codex remains pinned to 0.170.0.

## Changes

- Install the matching, checksum-pinned `codex-code-mode-host` executable beside
  `codex` in a newly built and signed Linux x86-64 image. Image qualification
  checks that the companion executable is present and can start.
- Test the client on Python 3.9 through 3.14 on both Linux and macOS.
- Improve release draft discovery and resumption, update packaging and GitHub
  Actions dependencies, and configure automated dependency updates.
- Record the v0.1.0 representative-cluster qualification and add Conda badges.

## Installation and upgrade

```sh
conda create -n codex-hpc --override-channels -c micknudsen -c conda-forge codex-hpc=0.1.1
conda activate codex-hpc
codex-hpc setup --host my-cluster
codex-hpc connect '~/projects/example' --host my-cluster
```

For an existing environment, install `codex-hpc=0.1.1` from the same channels,
then rerun `codex-hpc setup` to activate the matching helper and new image.

The package requires Python >=3.9 and supplies OpenSSH. The login host needs
Python 3, curl, Apptainer with PEM verification support, and access to GitHub
Releases for cold setup. Compute nodes need Linux x86-64, Slurm and compatible
Apptainer execution, with SSH through the login host and shared workspace paths.

## Validation and limitations

Publication requires all twelve Linux/macOS Python matrix jobs, signed-image
qualification, seven remote command suites against a fresh installation of the
exact Conda package with the real SIF, and installed setup/connect compatibility.
Publication also verifies a fresh installation from the `micknudsen` channel and
independently checks release assets, checksums and the image signature. Final
source and successful run links will be recorded below after these gates pass.

Automated SSH, Slurm and login checks use controlled peers. The companion startup
probe does not establish a successful authenticated Codex command or file-editing
tool call. The [v0.1.0 real-cluster report](https://github.com/micknudsen/codex-hpc/blob/master/docs/qualification/v0.1.0-2026-11-21.md)
records site qualification of the previous artifacts; the new v0.1.1 image has
not been separately qualified on that cluster.

Only one workspace and one Linux x86-64 node/task per session are supported.
