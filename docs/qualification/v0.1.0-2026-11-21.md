## Reproduction and probe evidence

Use the [installation, prerequisites and recovery instructions](../../README.md).
Choose an authorized host, fresh independent shared data/cache/state roots, and
a disposable workspace whose path contains a space or Unicode. Keep all site
values private. The tested public command pattern was:

```sh
conda create -n codex-hpc-test --override-channels \
  -c micknudsen -c conda-forge python=3.12 codex-hpc=0.1.0
conda activate codex-hpc-test

codex-hpc setup --host "$qualification_host" \
  --data-root "$qualification_data" --cache-root "$qualification_cache" \
  --state-root "$qualification_state"
# Repeat setup with the identical arguments for the warm case.

codex-hpc connect "$qualification_workspace" --host "$qualification_host" \
  --data-root "$qualification_data" --cache-root "$qualification_cache" \
  --state-root "$qualification_state" --cpus 2 --mem 4G --time 00:15:00
```

The exact executed scripts are [qualification_probe.py](probes/qualification_probe.py)
and [resource_probe.py](probes/resource_probe.py). Their local and remote hashes
matched the hashes retained in [v0.1.0-results.json](v0.1.0-results.json).
Copy the scripts into the disposable workspace. Create harmless, uniquely owned
sentinels in its sibling, personal home and selected persistent state root. Place
their absolute paths and the canonical workspace path in a runtime-only file:

```json
{"workspace":"/absolute/workspace æ test","sentinels":["/absolute/sibling/sentinel","/absolute/home/sentinel","/absolute/state/sentinel"]}
```

Name that file `probe-input.json`. Inside the real interactive Codex UI, shell
mode ran `!python3 qualification_probe.py first` and
`!python3 resource_probe.py`. The probes only inspect limits/mounts, read the
harmless sentinels, and create qualification marker/result files. The client,
remote helper, image, Codex executable and transport were not substituted.

Exit with `/quit`, verify the exact job is gone, reconnect with the same roots,
then run `!python3 qualification_probe.py second`. The first-session workspace
marker must exist and the first-session home marker must not. A node-side watcher
started while the second allocation was active polled only that session's exact
scratch path, confirmed removal on exit, and terminated. This avoids relying on
post-allocation node SSH, which the site's access policy rejects.

For cancellation, a third public connect used `--time 00:01:00`; Ctrl-C was sent
after its job ID printed and while it was pending. Query only the recorded job ID
with `squeue`. Empty output or an invalid-job response establishes that it is no
longer active. Remove only the sentinel and runtime-path files created for this
run. Do not archive authentication logs or the runtime input/scratch-path files.
